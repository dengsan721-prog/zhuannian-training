# 「学会说话，矛盾自化」点评工具交接规格

日期：2026-07-28  
状态：核心方向已由用户确认，供新的 Codex 任务窗口直接接管

## 1. 产品定位

这是一个独立于“转念训练”但可与其衔接的极简点评工具。

用户把任何一个人的一句话、一个动作或自己观察到的一件小事填写进去，工具立即生成三种不同风格、可以直接说出口的真诚点评。

产品主题：

> 学会说话，矛盾自化。

产品目标不是教用户空泛夸人，而是训练用户从真实、具体的小行为里，看见一个人的优点、亮点、特点、能力、品格、人格力量及其对家庭、团队或社会的积极意义，并把这种“看见”准确地表达出来。

## 2. 最高内容规则

每条点评必须形成可核对的证据链：

> 具体场景 → 可观察的小行为或语言 → 行为体现的内涵 → 给别人带来的影响或触动

禁止只输出“你真棒”“你很善良”“你很有责任心”等没有场景证据的标签。

点评可以上升到品格和人格，但不能凭一次行为武断定义整个人。优先使用：

- “这个动作让我看见了你……的一面”
- “这件小事里藏着……”
- “从你刚才……的处理里，我感受到……”
- “也许这只是一个很小的动作，但它体现了……”

避免使用：

- “你就是一个……的人”
- “这足以证明你永远……”
- 虚构用户没有提供的时间、动作、语言、动机或结果
- 讨好、吹捧、讽刺、道德绑架和刻意煽情

## 3. 点评公式

### 3.1 家人、亲人

> 人 + 优点或品格 + 证明它的具体场景

表达时建议先说行为，再说内涵，减少给人“被教育、被贴标签”的感觉。

### 3.2 挚友、同学、闺蜜、发小、战友等

> 人 + 共同经历中的具体场景 + 准确形容词或真实感受

### 3.3 陌生人、弱关联对象、首次见面对象

> 人 + 观察到的真实小行为 + 让人触动的亮点或社会意义

必须自然、克制，不刻意套近乎。

### 3.4 朋友圈

只点评真实有感觉的正面内容，不对负面内容妄加判断：

1. 看到了什么 + 想起了什么 + 触动或感慨
2. 看到了什么 + 学到了什么

“只点评正面”只适用于公开点评表达，不得用于掩盖暴力、控制、伤害、不公或安全风险。

## 4. 首版极简操作

首版建议只保留一个主要页面和一个结果状态。

### 输入区

1. 关系类型：家人 / 亲近的人 / 同事 / 陌生人 / 朋友圈
2. 一个主输入框：
   - 标签：“你看见他做了什么、说了什么？”
   - 提示：“尽量写一个具体动作、一句话或一个小细节。例如：下雨时，他停下来替后面的老人扶住了门。”
3. 主按钮：“生成三种点评”

关系类型使用轻量单选标签，不增加问卷。首版不要求用户填写姓名、手机号、班级码或长篇背景。

### 输出区

一次生成三张点评卡：

1. **温暖真诚**：重感受、关系和温度；
2. **生动有画面**：有细节、有画面，可带少量自然趣味；
3. **简洁有力量**：适合当面表达、微信或朋友圈回复。

三种结果必须基于同一组用户事实，但表达角度、节奏和语言风格不同，不能只是替换几个近义词。

每张卡只提供：

- “复制”
- “换一句”

不自动发送，不要求用户必须表达，也不默认保存原始输入。

## 5. 三种结果的示例

用户输入：

> 刚才下雨，一个年轻人自己淋着雨，还停下来替后面的老人扶住了门。

温暖真诚：

> 刚才雨那么大，你自己已经淋湿了，还停下来替后面的老人扶住那扇门。这个动作只有几秒，却让我看见了你对陌生人的体谅。谢谢你让一个普通的雨天，多了一点人与人之间的温度。

生动有画面：

> 雨下得很急，大家都在赶路，你却为身后的老人把脚步慢了下来。门只扶了几秒，善意却被很多人看见了。一个人的修养，常常就藏在这种没人提醒的小动作里。

简洁有力量：

> 你刚才淋着雨还替老人扶门，这个小动作让我看见了你的善意和教养。社会的温度，往往就是被这样的人悄悄托住的。

## 6. 全产品语言风格

内容丰富，操作极简。

文案默认比例：

- 70% 温暖、有力量；
- 20% 生动、有画面；
- 10% 轻松、有趣。

每条核心文案尽量做到：

- 有具体事实，不空泛；
- 有鲜活画面，不堆砌辞藻；
- 有真实亮点，不虚构动机；
- 有情绪温度，不说教；
- 有一点语言记忆点，但不过度玩梗；
- 适合直接说出口，可读、自然、有人味。

严肃冲突、受挫、亲子敏感或安全相关内容减少玩笑；日常小摩擦可以适度加入轻松表达。每条点评最多使用一个比喻，避免文艺腔和模板腔。

## 7. 内容生成字段

生成器内部至少应从输入中识别或组织以下字段：

- `relationshipType`：关系类型；
- `observedContext`：具体场景；
- `observedBehavior`：可观察行为或原话；
- `strengthCandidates`：可能体现的优点或能力；
- `characterMeaning`：可能体现的品格或人格力量；
- `positiveImpact`：对个人、家庭、团队或社会的意义；
- `speakerFeeling`：点评者真实、克制的感受；
- `commentWarm`：温暖真诚版；
- `commentVivid`：生动有画面版；
- `commentConcise`：简洁有力量版。

如果用户输入过于笼统，例如只写“他很好”，工具不应编造场景。应提示：

> 再给我一个小细节吧：他具体做了什么，或说了哪句话？

## 8. 质量验收标准

每条生成结果必须通过以下检查：

1. 是否复用了用户提供的真实动作或语言？
2. 是否明确写出了动作发生的场景？
3. 优点或品格是否能由该行为合理支撑？
4. 是否没有虚构人物动机、结果和背景？
5. 是否自然得像真人会说的话？
6. 三种版本是否有明显风格差异？
7. 是否避免空泛夸奖、标签化和过度拔高？
8. 是否兼顾可读性、生动性、趣味性与真诚？
9. 是否可以直接复制使用？
10. 是否没有把伤害、控制或不公强行正向化？

任何缺少“场景或小行为证据”的点评均不合格。

## 9. 与转念工具的关系

两个工具保持独立入口：

- 转念工具：改变自己对事件的第一种解释；
- 点评工具：把看见的正面价值说出来。

转念工具完成后，可以把当前场景事实带入点评工具，自动生成三种点评；但点评工具也可以单独使用。

两者衔接时仍不得增加转念训练的必经步骤。点评作为结果页的可选出口，用户点击后进入独立点评工具。
